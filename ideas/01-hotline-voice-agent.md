## Problem Statement

AI agents are getting wallets. Every agent-payments demo shows the agent spending. Almost none show the human being asked first, in a way that reaches them wherever they are. Screens need an app open. Push notifications get swiped. A phone call interrupts.

Hotline is an onchain agent on Arc testnet you reach by dialing a phone number. You talk, it acts within limits you set. When something happens onchain that crosses a limit, it calls *you*, explains, and waits for a spoken yes. The phone call is the guardrail.

Target: UBC 2026 Hackathon, Agentic Payments & AI track, Best use of Arc, ElevenLabs + QuickNode bounties.

## What Makes This Cool

- **The phone rings on stage.** Mid-demo, a testnet USDC transfer lands in the agent's wallet. The presenter's phone rings. The agent explains what arrived and asks permission to act. The room hears the whole thing.
- **Guardrails you can hear.** "That's above your 50 USDC limit, I need you to say yes." Policy tiers aren't a config page, they're dialogue.
- **No app.** Any phone, including a flip phone. Zero install. The phone number is the identity.
- **The agent pays its own way (stretch).** It buys a price quote from an x402-gated API for a fraction of a cent of USDC, and the ledger shows the micropayment next to the human-approved transfers.

## Premises (agreed)

1. The phone call is the guardrail. All prior voice-crypto projects found (Cymatic, Call DeFAI Engine, Baseline, VoiceVault, several ETHGlobal entries) are inbound-only. Outbound approval calls are the differentiator and map directly to the track's "human approval for large transactions."
2. Arc **testnet**, faucet USDC, zero real funds. (Revised from mainnet at Robert's request.) Consequence: our own policy engine is the enforcement layer; Circle policies are configured for mainnet parity but documented as non-enforcing on testnet.
3. Solo TypeScript, zero custom contracts. Agent composes existing protocols via viem and Circle's wallet SDK.
4. Trigger pipeline: QuickNode Streams (Arc testnet) → webhook → decision loop → ElevenLabs outbound call. Earns the QuickNode bounty.
5. Scope: inbound skill set, one outbound scenario done perfectly, policy tiers, audit dashboard, x402 as stretch. No mobile app.

### Approach B: Policy engine is the product (CHOSEN)
Everything in A, plus Circle Developer-Controlled Wallets SDK so the Arc judge sees Circle tooling, plus three policy tiers (AUTO / CALL / BLOCK), plus an x402 flow where the agent pays per request for data, plus a one-page audit dashboard.
Effort L. Risk Med-High. Six moving parts for one person. Mitigated by cut lines below.

### Approach C: Outbound only
A watchdog you talk to once, then it only ever calls you. Sharpest story, fewest parts, but loses the inbound conversation the ElevenLabs judge wants.

### Architecture

```
  Your phone  <── Twilio ──>  ElevenLabs Agent  ──server tools (HTTPS+secret)──>  Backend (Node/TS)
       ^                            ^                                               │
       │ outbound call              │ POST /v1/convai/twilio/outbound-call           ├── Policy engine (AUTO/CALL/BLOCK)
       └────────────────────────────┘                                               ├── Ledger (SQLite): every decision, reason, tx
                                                                                    ├── Wallet: Circle Dev-Controlled Wallet SDK, ARC-TESTNET
                                                                                    │     fallback: viem + local key
                                                                                    ├── Chain reads/writes via viem (Arc testnet RPC)
                                                                                    ├── POST /streams/webhook  <── QuickNode Streams (USDC Transfer logs → agent wallet)
                                                                                    ├── GET  /api/*           ──> Dashboard (single page, SSE live ledger)
                                                                                    └── x402 client → self-hosted x402-gated "quote" API (stretch)
```

**ElevenLabs server tools** (the agent calls these mid-conversation):
- `get_balance()` → USDC balance, recent activity
- `propose_action(kind, params)` → runs policy engine, returns `{action_id, decision: AUTO|CALL|BLOCK, reason, summary}`. AUTO executes immediately and returns tx hash. CALL returns "needs spoken confirmation." BLOCK returns the rule that blocked it.
- `confirm_action(action_id, approved: bool)` → executes or cancels a CALL-tier action. Idempotent on action_id.
- `get_rules()` / `set_rule(rule)` → read and update caps, allowlist, approval threshold, by voice.

**Decision loop** (this is the README section the track judge reads):
1. Intent arrives (spoken command via tool call, or onchain event via Streams webhook).
2. Normalize to an Action `{kind: send|swap|bridge|pay_api, to, amount, token}`.
3. Policy engine evaluates in order: contract/recipient blocklist → BLOCK; recipient not on allowlist and amount > allowlist-bypass cap → BLOCK; amount > per-tx cap → BLOCK; daily spend + amount > daily cap → BLOCK; amount > approval threshold → CALL; else AUTO.
4. AUTO: execute, log, confirm on the call. CALL: if already on a call, ask now; if not, place an outbound call with the action context in `conversation_initiation_client_data`, ask, wait for `confirm_action`. BLOCK: explain the rule, log, do nothing.
5. Every path writes a ledger row: timestamp, source (voice|stream|x402), action, decision, rule that fired, tx hash or null, call conversation_id.
6. Safety limits: per-tx cap, daily cap, recipient allowlist, contract blocklist, approval threshold, 10-minute expiry on unconfirmed CALL actions, idempotency on action_id, kill switch (`set_rule paused=true` by voice or dashboard).

**Outbound scenario (the climax):** QuickNode Stream filtered to `Transfer(address,address,uint256)` logs on the Arc testnet USDC contract where `to == agent wallet`. Webhook → backend creates a proposed action from the user's standing rule (e.g., "when idle balance exceeds 100 USDC, move the excess to the savings address" or "swap 50% to X"). Policy engine says CALL (because it moves funds the user didn't just ask to move). Backend places an outbound call. Agent: "You just received 200 USDC from 0x12…ab. Your rule moves anything over 100 to savings. Want me to send 100 now?" "Yes." Executes. Reads back the short tx hash.

**x402 stretch:** the agent's `get_quote(pair)` tool hits a self-hosted endpoint that returns HTTP 402 with payment requirements; the agent pays sub-cent USDC and retries. Prefer Circle Agent Nanopayments if it supports Arc testnet; otherwise a direct USDC transfer on Arc testnet to the API's wallet using the x402 header format. Either way the ledger shows a `pay_api` row. This is track objective #1 ("agents pay for APIs per request") made visible.

**Dashboard:** one page. Wallet balance, current rules, live ledger via SSE, link to each call's ElevenLabs conversation. No auth beyond a shared link. Exists so the judge has something to look at while the phone is ringing.
